| 항목 | 결정 |
|---|---|
| 방 연결 | **상하좌우 4방향**. 사다리·구멍으로 위아래 방도 이어짐 |
| 길 여는 방법 | **전부**: 캐릭터 고유 능력, 스위치·장치, 열쇠, 부서지는 벽(숨은 길), **특정 적 처치** |

참고 범위: 한 화면 단위 방이 촘촘하게 이어진 성 탐험이라는 장르 감각만 참고한다. 특정 게임의 맵·방 구성·퍼즐을 옮기지 않는다(DESIGN_DIRECTION §2).

## 2. 방과 격자

- 방 하나 = 한 화면 = **32×18칸**, 1칸 = 30단위(그림 60px, scale 2). 960×540 단위로 지금과 같다.
- 칸 문자:

| 문자 | 뜻 |
|---|---|
| `.` | 빈칸 |
| `#` | 벽·바닥(통과 불가) |
| `-` | 한쪽 발판: 위에서만 설 수 있고 아래·옆에서는 통과. 아래(↓)+점프로 아래로 내려감 |
| `H` | 사다리: 통과 가능. 매달려 오르내림. 사다리 맨 윗칸의 윗면은 위에서 설 수 있음(한쪽 발판처럼) |

- **방 사이 연결:** 방 가장자리 칸이 `#`가 아니면 그 칸은 "열림"이다. 열린 가장자리 칸 옆에는 반드시 이웃 방이 있어야 하고, 이웃 방의 맞닿는 칸도 열려 있어야 한다. 예를 들어 (x,y) 방의 오른쪽 끝 열 r행이 열려 있으면, (x+1,y) 방의 왼쪽 끝 열 r행도 열려 있어야 한다. 위아래도 같다.
- **방 이동:** 몸 중심이 화면 밖으로 나가면 그 방향의 이웃 방으로 간다. 좌표는 화면 크기만큼 옮기고(가로 ±960, 세로 ±540), 다른 축 좌표와 속도는 유지한다. 위로는 사다리나 점프로, 아래로는 구멍으로 떨어져 이동한다. 전환은 즉시 일어나고, 화면 효과(짧은 암전 등)는 렌더러가 선택한다.

## 3. 사다리 (새 동작)

- 사다리 칸과 몸 중심 x가 겹친 상태에서 ↑ 또는 ↓를 누르면 **매달린다**(`climbing: true`). 사다리 꼭대기 위에 서 있을 때 ↓를 누르면 내려가며 매달린다.
- 매달린 동안:
  - 중력이 없고 가로 속도는 0이다. ↑/↓를 누르면 `CONFIG.heroes.*.climbSpeed`(px/틱)로 움직이고, 아무것도 누르지 않으면 그 자리에 멈춘다.
  - 몸 가로 중심은 사다리 칸 중심에 맞춘다.
  - 점프하면 사다리에서 떨어지며 일반 점프를 한다(좌우 입력 방향으로).
  - 사다리 꼭대기를 넘어 오르면 꼭대기 윗면에 선다. 사다리 아래 끝에서 바닥에 닿으면 선다.
- `climbSpeed`는 조절 패널에 추가한다. 초기값은 Ethan 2.0, Noah 2.4를 권장한다.

## 4. 길을 여는 물건 (objects)

좌표는 **칸 단위**(`x`, `y`, `w`, `h`, 기본값 `w=h=1`)이고 방마다 둔다. `id`는 구역 전체에서 유일하다.

| type | 필드 | 동작 |
|---|---|---|
| `door` | `id, x, y, w, h, open` | 닫혀 있는 동안 벽처럼 막힌다. `open` 조건이 충족되면 열리고(이벤트 `door`) 계속 열려 있다 |
| `switch` | `id, x, y, kind?, hero?` | 몸이 스위치 칸(1×1)과 겹친 상태에서(공중이어도 됨) **조사(interact)**를 누르면 켜진다(이벤트 `switch`, 한 번 켜지면 유지). `hero`가 있으면 그 주인공만 켤 수 있고, 다른 주인공이 누르면 이벤트 `denied`만 발생한다. `kind`는 그림 구분용(`lever` 레버, `light` 빛 장치) |
| `key` | `id, x, y, name` | 몸이 닿으면 줍는다(이벤트 `pickup`). 같은 `name`을 여러 개 가질 수 있다 |
| `breakable` | `id, x, y, w, h` | 부서지기 전에는 벽처럼 막힌다(닫힌 문과 함께 투사체도 막는다). 플레이어의 공격 판정(근접·투사체)에 닿으면 부서진다(이벤트 `break`). 투사체는 그 자리에서 사라진다 |
| `target` | `id, x, y, hp, w?, h?` | 지금의 시험 표적과 같다(맞으면 hp 감소, 움직이지 않음). 크기 기본값은 1×2칸(30×60). 방을 나갔다 와도 hp가 유지된다. hp 0이 된 표적은 공격을 막지 않는다 |

`door.open` 조건(하나만 쓴다):

| 조건 | 열리는 때 |
|---|---|
| `{ "switch": "<switch id>" }` | 그 스위치가 켜졌을 때(다른 방의 스위치여도 됨) |
| `{ "key": "<name>" }` | 그 열쇠를 가진 채 몸이 문에 닿을 때. 열쇠 1개를 쓴다 |
| `{ "cleared": ["<target id>", ...] }` | 적힌 표적이 모두 hp 0이 되었을 때 |

**캐릭터 고유 능력**: Ethan은 빛 장치(`switch`, `kind:"light"`, `hero:"ethan"`), Noah는 높은 레버(`switch`, `kind:"lever"`, `hero:"noah"`)를 켤 수 있다. Noah 전용 레버는 Noah의 높은 점프로만 닿는 위치에 둔다.

방을 나갔다 돌아와도 스위치, 열린 문, 부서진 벽, 주운 열쇠, 표적 hp는 모두 유지된다.

## 5. 입력과 조작

- 입력에 `up`, `down`, `interact`를 쓴다(누르고 있는 상태, 누른 순간 판정은 `sim.js`가 한다).
- 키보드: ↑/W 위, ↓/S 아래, **E 조사**. 기존 키(A/D, Space/K/Z, J/X, Q/Tab)는 유지한다.
- 모바일:
  - 조이스틱을 **두 축(상하좌우)**으로 바꾼다. 방향 판정에는 데드존을 둔다.
  - **조사 버튼**(`data-action="interact"`)을 추가한다. FOUNDATION_SPEC §7-1의 배치 기준(캔버스를 가리지 않음, 44px 이상)을 지킨다.
- 지도: 키보드 **M**과 모바일 지도 버튼으로 연다. 가본 방만 보이고, 현재 방은 강조한다. 1단계에서 정한 인터페이스 규칙(디버그 숨김 등)을 유지한다.

## 6. 시뮬레이션 계약 (추가)

1단계 계약(`FOUNDATION_SPEC.md` §4)은 **그대로 유지**한다. `createWorld({ room, spawn, hero })` 한 방 모드와 1단계 검사 51개는 계속 통과해야 한다. 아래를 추가한다.

```js
const world = HKSim.createWorld({ area, hero });  // 구역 모드. 시작 위치는 area.start
world.roomId                                     // 현재 방 id
HKSim.step(world, { left, right, up, down, jump, attack, swap, interact });
// 추가 이벤트: {type:'room', from, to, dir:'left'|'right'|'up'|'down'}
//             {type:'switch', id} {type:'denied', id} {type:'pickup', id, name}
//             {type:'door', id} {type:'break', id}
HKSim.getPlayer(world).climbing                  // boolean
HKSim.getMap(world)    // { current, rooms: [{ id, pos:[x,y], visited }] }
HKSim.getFlags(world)  // { switches:{id:true}, doors:{id:true}, broken:{id:true}, keys:{name:count}, picked:{id:true}, cleared:{targetId:true} }
```

구역 데이터 형식(`next/areas/area1.json`):

```json
{
  "version": 1, "cols": 32, "rows": 18, "tile": 30,
  "start": { "room": "gate", "x": 90, "y": 382 },
  "rooms": {
    "gate": { "pos": [0, 0], "name": "성문", "grid": ["################################", "..."], "objects": [] }
  }
}
```

- `grid`는 18개 문자열이고, 각각 32글자다.
- `start`의 `x`, `y`는 몸의 왼쪽 위 좌표(게임 단위)다.
- 방 이름은 화면 표시용이다.

## 7. 시범 구역 요구사항 (8~12방)

구역 설계(방 배치, 퍼즐)는 Codex가 하고 사용자가 판단한다. 다음은 반드시 포함한다(자동 검사).

- 방 8~12개. 가로로 이어진 곳과 **위아래로 이어진 곳이 각각 1개 이상**
- 사다리 1개 이상, 한쪽 발판 1개 이상
- 문 종류별 1개 이상: 스위치 문, 열쇠 문, 표적 처치 문
- Ethan 전용 빛 장치 1개 이상, Noah 전용 높은 레버 1개 이상
- 부서지는 벽 1개 이상. 그 뒤에 숨은 방이나 보상 칸이 있다
- 되돌아가야 풀리는 구조 1개 이상(먼 방의 스위치가 앞 방의 문을 연다)
- 지름길 1개 이상: 한쪽에서만 열 수 있는 문을 열면 시작 방 쪽으로 짧게 돌아올 수 있다
- **완주 기록** `next/areas/area1.walkthrough.json`
  - 시작부터 입력만으로 다음을 모두 해낸 뒤 **시작 방으로 돌아온다**: 모든 방 방문, 모든 스위치 켜기, 모든 문 열기, 모든 부서지는 벽 부수기, 모든 열쇠 줍기, 모든 표적 처치
  - 형식: `{ "hero": "ethan", "inputs": [{ "keys": "right,jump", "ticks": 12 }, ...] }`. `keys`는 쉼표로 구분한 입력 이름이고, 빈 문자열은 입력 없음이다.
  - 자동 검사가 이 기록을 그대로 재생해 확인한다(결정적 시뮬레이션이므로 가능).
  - 교대(swap) 입력으로 두 주인공을 모두 써야 한다.

## 8. 그림 (ART_DIRECTION 기준, scale 2)

**필수**
- 타일:
  - 기존 `floor-top`, `wall-fill`, `ledge`(한쪽 발판에 사용)
  - 새 칸 `ladder`(60×60, 위아래로 이어 붙여도 이음새가 보이지 않음)
- 물건 시트 `objects.png`:
  - 이름별 위치를 `manifest.json`의 `objects`에 적는다. 형식: `{ "door-closed": { "file", "x", "y", "w", "h" } }`
  - 필수 이름: `door-closed`, `door-open`, `lever-off`, `lever-on`, `light-off`, `light-on`, `key`, `breakable`, `locked-door`(열쇠 문)

**선택:** 방마다 다른 배경

모든 그림은 같은 64색 팔레트, 투명도 0/255, 원래 해상도 규칙을 따른다.
