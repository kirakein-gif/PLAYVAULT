## 2. Noah 3단 콤보 (연타)

`CONFIG.heroes.noah.weapon`에 다음을 더한다. 1단 값은 지금 `weapon`의 값과 같아야 한다(1단계 검사 유지).

```js
combo: [
  { damage: 22, range: 66, height: 46, activeTicks: 9,  recoveryTicks: 18 },             // 1단: 지금과 같음
  { damage: 22, range: 72, height: 46, activeTicks: 9,  recoveryTicks: 22 },             // 2단: 조금 더 길게 (§2-1에서 18→22)
  { damage: 44, range: 84, height: 60, activeTicks: 12, recoveryTicks: 34, lunge: 10 }   // 3단: 크게, 앞으로 디딤 (§2-1에서 30→34)
],
comboWindowTicks: 14   // §2-2에서 20으로
```

- **k단이 시작된 틱을 t라 하면** 다음 공격은 `t + recoveryTicks` 이후에만 나간다(지금의 cooldownTicks와 같은 뜻).
- **이어 치기:** t+1 ~ `t + recoveryTicks + comboWindowTicks - 1` 사이에 공격을 **누른 순간**이 있으면 다음은 (k+1)단이다. 회복 중에 누른 것은 **미리 입력**으로 기억했다가 `t + recoveryTicks`에 바로 나간다. 3단 다음은 1단이다.
- 그 사이에 누르지 않으면 콤보가 끊겨 다음 공격은 1단이다.
- 3단의 `lunge`: 공격 판정이 있는 동안 바라보는 방향으로 모두 10단위 앞으로 디딘다. 벽·닫힌 봉쇄물은 뚫지 않는다.
- 교대하면 콤보와 미리 입력은 사라진다(지금처럼 근접 판정도 사라짐).
- 공중·사다리에서도 콤보는 이어진다. 공중 3단의 디딤은 가로로만.
- 이벤트: `{ type: 'attack', hero: 'noah', step: 1|2|3 }`.

## 2-1. Noah 베기 보완 (2026-11-02, PR #20 손맛 확인 후)

사용자: "에단의 충전 공격은 괜찮다. 노아의 3단 베기는 너무 빨라서 움직임이 잘 안 보이고, 궤적만 여기저기 다른 느낌." → **자세 멈춤 + 리듬 조금 느리게** 선택.

측정(PR #20 `bf87c75`): 베기 동작 길이 1·2단 9틱(0.15초), 3단 12틱(0.2초). 가장 오래 보이는 자세가 1·2단 3틱, 3단 4틱이고 동작이 끝난 뒤 다음 공격까지 9~18틱은 서 있는 자세로 돌아가 있었다.

- **리듬:** `combo[1].recoveryTicks` 18 → **22**, `combo[2].recoveryTicks` 30 → **34**. 1단은 18 그대로(1단계 검사·기본 공격 감각 유지). 창(`comboWindowTicks`)·피해·사거리·판정 시간은 그대로.
- **동작 길이:** 각 단의 베기 동작(`attack`, `attack-2`, `attack-3`) 전체 길이(ticks 합)가 그 단의 `recoveryTicks - 2` 이상. 다음 공격 직전까지 몸 동작이 이어진다. → §2-2에서 `recoveryTicks` 이상으로 강화
- **자세 멈춤:** 각 동작에서 가장 오래 보이는 프레임(휘두른 직후의 핵심 자세)이 **4틱 이상**. 첫(준비) 프레임은 지금처럼 2틱 이하.
- **맞힐 때:** 근접 공격이 표적·적에 맞으면 렌더러가 Noah의 그 프레임을 **3틱(3단은 5틱) 더 붙잡고** 맞은 표적을 짧게 밝힌다. **게임 시간(시뮬레이션)은 멈추지 않는다** — 멈추면 콤보 타이밍·완주 기록 재생이 모두 어긋나기 때문이다. 그림 표시만의 효과다.
- 각 단의 몸 동작이 서로 달라 보이게 한다(1단 내려 베기, 2단 올려 베기, 3단 크게 가로 베기 + 디딤). 궤적만 다르고 몸이 비슷하면 안 된다.
- 사용자 추가 의견: "무언가 촥~ 촥~ 촥 하는 느낌이 나야 할 것 같아요. 격투 게임의 3단 콤보처럼." → 한 타 한 타가 **끊어져 들리는 박자**와 **맞는 순간의 손맛**을 목표로 아래를 더한다(모두 그림 표시 효과, 게임 시간은 그대로).
  - **박자:** 1→2단 18틱, 2→3단 22틱으로 빠른·빠른 뒤 마무리. 각 베기는 준비(2틱 이하) → 휘두름 → **멈춘 핵심 자세** → 거두기 순서로, 휘두름은 1~2프레임으로 짧게 끊고 멈춘 자세를 길게 둔다(빠르게 긋고 멈추는 대비가 "촥"이 된다).
  - **맞는 순간:** 위 "맞힐 때"의 자세 붙잡기(1·2단 3틱, **3단 5틱**)와 함께 맞은 표적·적을 1~2틱 하얗게 밝히고, 맞은 쪽 그림을 바라보는 반대 방향으로 2~4픽셀 밀었다 돌아오게 한다.
  - **마무리 무게:** 3단이 맞으면 화면을 6틱 동안 2~3픽셀 흔든다(1·2단은 흔들지 않음). 3단 베기 효과는 1·2단보다 굵고 길게.
  - **효과음은 넣지 않는다**(2026-11-02 사용자 결정: "소리가 안 나도 느낌으로 소리가 나는 것처럼 충분히 가능합니다"). "촥" 느낌은 위의 그림 표시(긋고 멈추기 대비, 자세 붙잡기, 표적 밝힘·밀림, 3단 흔들림)만으로 낸다. 효과음은 4단계(사운드) 범위로 그대로 둔다.
- 자동 검사: `weapons-contract.cjs`(리듬), `pixel-assets.cjs`(동작 길이·자세 멈춤).

## 2-2. Noah 콤보 연결 (2026-11-02, PR #20 `091e41b` 손맛 확인 후)

사용자: "촥 하는 느낌은 있는데 세 모션의 연결이 좀 부자연스럽다. 끊기기도 하고."

측정(Claude Code, `091e41b`):
- **서 있는 자세가 끼어듦:** 각 단 동작 길이가 `recoveryTicks - 2`(16·20틱)로 끝나, 표적을 맞히지 않으면 다음 단이 나가기 전 2틱 동안 idle(움직이면 run) 자세가 보인다. §2-1의 "`recoveryTicks - 2` 이상" 기준이 이 틈을 허용했다(Claude Code 규격 결함).
- **자세가 이어지지 않음:** 1단 마지막 프레임과 2단 첫 프레임의 실루엣 겹침(기준점 맞춤 IoU) 0.49, 2단→3단 0.48. 한 동작 안 이웃 프레임끼리도 0.46~0.69로 프레임 수(4)가 적어 동작이 뚝뚝 끊긴다.
- **박자를 조금만 놓쳐도 1단으로 돌아감:** 창이 회복 뒤 14틱(0.23초)이라, 사람이 자기 박자로 누르면 콤보가 끊기기 쉽다.

규칙:
- **틈 없음:** 각 단 동작 길이 ≥ 그 단의 `recoveryTicks`(18·22·34틱). 또 렌더러는 콤보가 이어질 수 있는 동안(창이 끝날 때까지) **그 단의 마지막 프레임을 유지**하고 idle·run으로 돌아가지 않는다. 다음 단이 나가면 바로 그 단의 첫 프레임으로.
- **이어지는 자세:** 앞 단의 마지막 프레임(거두기)이 다음 단의 첫 프레임(준비)으로 자연스럽게 넘어가게 그린다. 1단 끝 = 2단 시작, 2단 끝 = 3단 시작 자세가 거의 같아야 한다(기준점 맞춤 실루엣 겹침 **0.7 이상**). 격투 게임의 연속기처럼 앞 타의 거두기가 곧 다음 타의 준비가 된다.
- **부드러운 동작:** 각 단 **6프레임 이상**. 휘두름은 지금처럼 1~2프레임으로 짧게, 늘어난 프레임은 준비·핵심 자세 전후·거두기에 써서 자세 사이를 잇는다.
- **창 넓힘:** `comboWindowTicks` 14 → **20**(0.33초). 미리 입력·피해·사거리·회복은 그대로.
- 자동 검사: `weapons-contract.cjs`(창 20), `pixel-assets.cjs`(6프레임, 동작 길이 ≥ 회복, 연결 자세 겹침 0.7), `combo-render.cjs`(실제 화면에서 1→2→3단 사이에 idle·run이 끼지 않음).

## 2-3. Noah 콤보 동선 다시 짜기 — 치기 → 파고들어 올려 베기 → 크게 내려치기 (2026-11-02)

사용자: "2타째 올려치는 느낌이 잘 안 난다. 보통 올려치기가 들어가는 3단 콤보라면 1타를 치고, 2타 때는 좀 파고들어서 아래에서 위로 휘둘러 올리고, 3타째는 크게 휘둘러서 내려치는 느낌이 나야 하지 않을까."

측정(`00479e7`, 베기 효과의 프레임별 무게중심 이동): 1단 위→아래 82px(사실상 내려 베기), 2단 위로 10px(올려 베기가 거의 안 보임), 3단 가로로만 이동. 디딤(lunge)이 3단에 있었다. → 동선이 사용자 의도와 반대로 배치되어 있었다(§2 규격의 "2단 올려 베기, 3단 가로 베기 + 디딤" 문구 자체가 원인 — Claude Code 규격 결함).

**동선** (기준 그림: `docs/reference/noah-combo-keyposes.png` — 방향과 박자만 보여 주는 막대 그림이며 그림 양식 기준이 아님):

| 단 | 몸 | 칼 궤적 | 판정 |
|---|---|---|---|
| 1 치기 | 발을 고정하고 앞으로 짧게 | 거의 수평으로 앞으로 | 지금 1단 값 그대로(range 66, height 46) |
| 2 파고들어 올려 베기 | **한 걸음 파고들며 낮게 숙였다가** 몸을 펴며 | **아래 → 위**(크게 올라감) | range 64, **height 80**(위로 넓게), **lunge 12**(파고들기) |
| 3 크게 내려치기 | 칼을 **머리 위로 크게 들었다가** 발을 버티고 | **위 → 아래**(가장 큰 궤적) | range **90**, height 64, **디딤 없음** |

```js
combo: [
  { damage: 22, range: 66, height: 46, activeTicks: 9,  recoveryTicks: 18 },
  { damage: 22, range: 64, height: 80, activeTicks: 9,  recoveryTicks: 22, lunge: 12 },
  { damage: 44, range: 90, height: 64, activeTicks: 12, recoveryTicks: 34 }
],
comboWindowTicks: 20
```

- 피해·회복·창은 그대로. 2단 사거리는 줄었지만 파고들기 12로 실제로는 76까지 닿고, 3단은 2단에서 앞으로 나간 자리에서 90을 친다.
- §2-2(틈 없음, 연결 자세 겹침 0.7, 6프레임)와 §2-1(핵심 자세 멈춤, 타격 연출)은 그대로 지킨다. 연결: 1단 끝 → 2단 시작(낮게 숙인 준비), 2단 끝(칼이 높이 올라간 자세) → 3단 시작(머리 위로 든 준비)이 자연스럽게 이어진다. 올려 벤 칼이 그대로 머리 위로 올라가 내려치기 준비가 되는 흐름이다.
- **인물 크기 일정:** 모든 동작 프레임의 인물 크기(머리·몸 비율)는 idle과 같다. `00479e7`에서 1단·3단 일부 프레임이 idle보다 약 1.2배 커 보였다(검토 눈대중). 자동 측정은 시트마다 색·자세가 달라 신뢰할 수 없으므로 캡처 검토 항목으로 둔다.
- 자동 검사: `weapons-contract.cjs`(동선 수치·파고들기·3단 디딤 없음·3단만 닿는 거리), `pixel-assets.cjs`(베기 효과 궤적: 1단 수평 우세, 2단 위로 ≥ 20단위, 3단 아래로 ≥ 30단위이고 2단보다 큰 이동).

## 2-4. 각 베기는 기본 자세로 끝나고, 준비 동작은 그 베기 안에서 (2026-11-03)

사용자(미리보기 `eb1fdd2`): "훨씬 나아졌다. 근데 1타를 치고 나서 2타 칠 준비로 바로 엎드린다. 1타 치면 그냥 서 있고, 2타 치면 엎드렸다가 올려치고 하는 게 좋겠다. 2타에서 3타도 마찬가지."

원인: §2-2의 "앞 단 마지막 = 다음 단 첫 자세" 기준을 지키려고 다음 단의 준비(2단 숙이기, 3단 칼 들기)가 앞 단 끝에 붙었다. 측정(`eb1fdd2`, 서 있을 때 키 = 1.0): 1단 끝 0.58(엎드림), 2단 끝은 칼을 머리 위로 든 자세, 3단 끝 0.99. 버튼을 더 누르지 않아도 엎드리거나 칼을 든 채 멈춘다. → §2-2 기준의 부작용(Claude Code 규격 결함).

규칙:
- **기본 자세:** 세 단 모두 **같은 서 있는 기본 자세**로 끝난다(마지막 프레임 키 0.9~1.1, 세 단 끝 자세 실루엣 겹침 0.7 이상). 2·3단의 첫 프레임도 이 기본 자세다(§2-2 연결 겹침 0.7은 그대로 — 이제 "기본 자세 = 기본 자세"로 이어진다).
- **준비 동작은 그 단 안에서:** 2단은 기본 자세 → **숙이며 파고들기**(키 0.8 이하) → 올려 베기. 3단은 기본 자세 → **칼을 머리 위로 들기**(키 1.15 이상) → 내려치기. 숙이기·칼 들기 프레임은 아래 준비 시간 안에 시작한다.
- **준비 시간(시뮬레이션):** 준비 동작을 보이는 동안에는 아직 베지 않았으므로 판정도 늦춘다. `combo[1].startupTicks` **4**, `combo[2].startupTicks` **6**. 이 동안 판정·피해·디딤이 없고, 그 뒤 `activeTicks` 동안 판정. 1단은 0(누르는 즉시 — 1단계 검사 유지). 회복(박자)은 그 단 시작부터 세므로 그대로이고, 준비 + 판정은 회복 안에 끝난다.
- 동작 길이 ≥ 회복, 6프레임 이상, 핵심 자세 ≥ 4틱, 베기 궤적 방향(§2-3), 타격 연출(§2-1)은 그대로.
- 기준 그림 `docs/reference/noah-combo-keyposes.png` 아래에 이 원칙을 덧붙였다.
- 자동 검사: `weapons-contract.cjs`(준비 시간 값, 준비 동안 판정·피해 없음), `pixel-assets.cjs`(끝 자세 높이·세 단 끝 자세 같음·숙이기·칼 들기가 준비 시간 안에 시작).

## 3. Ethan 3단계 충전 사격 (누르고 있다가 놓기)

`CONFIG.heroes.ethan.weapon`에 다음을 더한다. 1단(지금의 룬탄)은 그대로다.

```js
charge: {
  stage2Ticks: 40, stage3Ticks: 80,
  shots: [
    { damage: 44, width: 26, height: 18, speed: 11.5 },                                   // 2단
    { damage: 66, width: 34, height: 24, speed: 12.5, burstRadius: 45, burstDamage: 33 } // 3단
  ]
}
```

- **누른 순간(공격 가능할 때):** 지금처럼 1단 룬탄이 바로 나간다(`attack`, level 1). 동시에 충전이 시작된다. 공격 대기 중에 누른 것은 지금처럼 무시하고 충전도 시작하지 않는다.
- **누르고 있는 동안:** 충전 틱이 늘어난다. 누른 순간부터 40틱이 되면 2단, 80틱이 되면 3단이 되고 그때마다 `{ type: 'charge', hero: 'ethan', level }` 이벤트가 한 번씩 난다.
- **놓은 순간:** 2단 이상이면 그 단계의 충전탄을 쏜다(`attack`, level 2|3). 2단 미만이면 아무것도 쏘지 않는다. 충전탄을 쏘면 공격 대기는 `cooldownTicks`부터 다시 센다.
- 충전탄도 **관통하지 않는다**(첫 표적·벽·봉쇄물·부서지는 벽에서 멈춤). 사거리·발사 높이는 1단과 같다.
- **3단 빛 터짐:** 3단 탄이 멈춘 자리(맞은 면의 가운데)를 중심으로 반지름 45단위 안에 몸이 걸치는 **다른** 표적·적에게 `burstDamage`. 직접 맞은 표적은 탄 피해만 받는다. 벽 너머도 반지름 안이면 맞는다(짧은 거리라 단순화). 부서지는 벽은 빛 터짐으로 부서지지 않는다(퍼즐 우회 방지). 이벤트 `{ type: 'burst', x, y, r }`.
- 충전 중에도 걷기·점프·사다리는 그대로 할 수 있다(이동 감속 없음 — 시험 후 조정 가능하도록 `charge.moveScale` 등을 넣지는 않는다).
- 교대하면 충전은 사라지고, 놓아도 아무것도 쏘지 않는다.
- `HKSim.getPlayer(world).charge` = `{ ticks, level }`. 충전 중이 아니면 `{ ticks: 0, level: 0 }`, 누른 뒤 2단 전에는 level 1.

## 3-1. Ethan 발사 위치 (2026-11-03)

사용자: "에단의 경우 탄을 발사하는 위치는 손인데, 탄이 나가는 위치는 몸 중앙이네요. 검토할 필요가 있을 것 같습니다." → 선택: **그림을 낮춰 중간 높이에서**.

측정(`eb1fdd2`, 게임 단위): 그림 속 손 — 공격 발사 프레임 발에서 51·몸 중심에서 앞 29, 충전 자세 50.5·22. 실제 탄은 몸 앞면(앞 21)·발에서 34(몸 가운데)에서 생겼다. 손보다 17단위(화면 약 34px) 아래.

판단: 탄을 손 높이(51)로 올리면 키 약 45보다 작은 적은 탄이 머리 위로 지나가 2차에서 작은 적을 맞힐 수 없다. 그래서 탄 높이는 조금만 올리고(34 → 40), 그림의 손을 그 높이로 내린다.

- `CONFIG.heroes.ethan.weapon.muzzle = { forward: 6, height: 40 }`: 탄의 몸 쪽 끝이 몸 앞면에서 `forward`만큼 앞, 탄의 세로 가운데가 발에서 `height`. 1·2·3단 탄 모두 같다. 왼쪽을 보면 좌우 반전.
- 그림: `attack`의 발사 프레임(1번)과 `charge`의 모든 프레임에서 탄을 내보내는 손이 발사 위치(몸 중심에서 앞 27, 발에서 40) ±4단위 안. manifest `hands`를 그 손 위치로 적는다. 팔을 앞으로 뻗어 손이 가슴 아래 높이에 오는 자세.
- 렌더러: 1단 룬탄·충전 빛(fx-charge)·2·3단 탄이 모두 이 위치에서 시작해 보이게.
- 한계: `pixel-assets.cjs`는 manifest에 적힌 `hands` 좌표를 검사하며, 실제로 그려진 손 픽셀은 재지 못한다. 그래서 캡처에 발사 위치 표시를 겹친 그림을 첨부해 눈으로 확인한다.
- 자동 검사: `weapons-contract.cjs`(muzzle 값, 1·2·3단 탄 생성 위치 좌우), `pixel-assets.cjs`(hands가 발사 위치 ±4단위).

## 4. 그림 (ART_DIRECTION 규칙: scale 2, 64색, 투명도 0/255, 원래 해상도, 경로 A)

| 이름 | 내용 |
|---|---|
| noah `attack-2`, `attack-3` | 4프레임 이상, 첫 프레임 2틱 이하(1단 `attack`과 같은 규칙). 2단은 올려 베기, 3단은 크게 가로 베기 + 디딤 |

| ethan `fx-charge` | 손에 모이는 빛 3프레임 이상, 반복. 2단·3단을 크기나 밝기로 구분(렌더러가 단계별로 다르게 그림) |

## 5. 입력·조작 패널

- 키보드·모바일 모두 지금의 공격 키·버튼을 그대로 쓴다(누르고 있기 = 충전). 모바일 공격 버튼은 누르고 있는 동안 계속 눌린 상태여야 한다.
- 조작 패널(F2)에 combo의 단계별 damage·range·recoveryTicks, comboWindowTicks, charge의 stage2Ticks·stage3Ticks·단계별 damage를 추가한다.
