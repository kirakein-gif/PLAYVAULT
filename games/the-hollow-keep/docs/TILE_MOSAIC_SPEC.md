| 항목 | 결정 |

## 2. 원칙

- 구역 화면은 **60×60px(30단위) 조각만으로** 만든다. 1920×1080 큰 배경(`bg-chapel.png`)은 구역 모드에서 쓰지 않는다. `?room=test` 시험 방은 지금처럼 써도 된다.
- 큰 것은 조각을 이어서 만든다. 창은 위·가운데·아래 조각을 쌓고, 가운데 조각을 반복해 높이를 맞춘다. 기둥과 깃발도 같다.
- 같은 조각이 반복되어도 단조롭지 않도록 **변형 조각**을 섞고, 어떤 변형을 쓸지는 칸 위치로 정한다(같은 방은 언제나 같은 모습).
- 조각이 격자에 딱 맞으므로, PR #14에서 보인 "배경 창이 벽 띠에 잘리는" 문제는 생기지 않는다.

## 3. 층과 조각

화면은 아래에서 위로 세 층이다.

| 층 | 내용 | 조각 이름(`manifest.tiles.cells`) |
|---|---|---|
| ① 뒷벽 | 벽이 아닌 칸(`#` 이외) 전부 | `back-1`, `back-2`, `back-3` (민무늬 변형 3종, 필수) |
| ② 장식 | 방의 `back` 격자에 적힌 칸 | `window-top/mid/bottom`, `pillar-top/mid/base`, `banner-top/mid/bottom`, `candle` (필수) |
| ③ 벽·발판·사다리 | `grid`의 `#`, `-`, `H` | `floor-top`, `wall-fill`, `wall-fill-2`, `wall-bottom`, `wall-left`, `wall-right`, `ledge`, `ladder` (필수) |

**벽 조각 고르기(③):** `#` 칸마다 이웃을 보고 고른다. 우선순위는 위 > 아래 > 옆 > 속이다.
1. 위 칸이 `#`가 아니면 `floor-top`(서는 면)
2. 아니고 아래 칸이 `#`가 아니면 `wall-bottom`(천장 아랫면)
3. 아니고 왼쪽이 `#`가 아니면 `wall-left`, 오른쪽이 `#`가 아니면 `wall-right`
4. 나머지는 `wall-fill`과 `wall-fill-2` 중 칸 위치로 고른다

방 밖은 `#`로 본다. 모서리 조각(`wall-top-left` 등)은 선택이다. 만들면 써도 된다.

**뒷벽 변형 고르기(①, `wall-fill` 변형도 같음):** `(열 × 7 + 행 × 13 + 방 id 글자 코드 합) % 3`처럼 칸 위치만으로 정하는 식을 쓴다. 매 프레임 바뀌거나 무작위이면 안 된다. 식은 Codex가 정하고 README에 적는다.

## 4. 방 데이터: `back` 격자

방마다 `back`을 둔다. `grid`와 같은 18줄 × 32글자다.

| 문자 | 뜻 | 그리기 |
|---|---|---|
| `.` | 장식 없음 | 뒷벽만 |
| `w` | 창 | 세로로 이어진 `w` 묶음의 맨 위 `window-top`, 맨 아래 `window-bottom`, 사이 `window-mid` |
| `p` | 기둥 | 같은 방식으로 `pillar-top` / `pillar-mid` / `pillar-base` |
| `b` | 깃발 | `banner-top` / `banner-mid` / `banner-bottom` |
| `c` | 촛대 | `candle` 한 칸 |

규칙:
- 장식 문자는 `grid`가 `#`인 칸에 둘 수 없다(벽 뒤 장식 금지).
- `w`, `p`, `b`는 세로로 **2칸 이상** 이어져야 한다(위·아래 조각이 모두 있어야 함).
- 장식은 뒷벽 층이다. 충돌·길에는 영향이 없다.

## 5. 다양성 기준 (자동 검사)

| 기준 | 값 |
|---|---|
| V1 장식 종류 | 방마다 장식 2종 이상, 구역 전체로 4종(`w`, `p`, `b`, `c`) 모두 사용 |
| V2 장식 양 | 방마다 장식 칸이 벽 아닌 칸의 3% 이상 25% 이하(비어 보이지도, 어지럽지도 않게) |
| V3 방 모양 차이 | 어떤 두 방을 비교해도 `#` 위치가 다른 칸이 58칸(전체의 10%) 이상 |
| V4 사다리 배치 | 사다리가 있는 열의 집합이 똑같은 방이 3개를 넘지 않음 |

반복 조각을 쓰는 것은 괜찮다. 막는 것은 **방 전체가 같은 틀을 복사한 것처럼 보이는 경우**다(PR #14: 8방이 같은 3층 뼈대, 같은 사다리 열). 밀도 기준(보완 §5 D1~D6)은 그대로 지킨다.

## 6. 방 이동 규칙 보완 (PR #14 검토에서 발견한 문제)

- **방 이동 직후 몸이 새 방의 벽·닫힌 봉쇄물·부서지지 않은 벽과 겹치면 방을 옮기지 않는다.** 이전 방 가장자리에 머물고, 그 축의 속도는 0이 된다. 걷기, 떨어지기, 점프, 사다리 모두 같다.
- 이유: PR #14에서 loft 사다리로 내려가면 gate 1행의 닫힌 `return-seal`을 그대로 통과했다. 방이 바뀌는 순간 몸이 이미 봉인과 겹쳐 있으면 충돌 판정이 막지 못한다.
- 봉쇄물이 열리면 평소처럼 지나간다.

## 7. 그림

- 위 조각은 모두 `tiles.png`(또는 `tiles` 매니페스트가 가리키는 파일)의 60×60 칸이다. 64색, 투명도 0/255, 원래 해상도를 지킨다.
- 뒷벽 조각은 이어 붙였을 때 이음새가 보이지 않아야 한다. 창·기둥·깃발 가운데 조각은 위아래로 반복해도 이어져야 한다.
- 뒷벽은 벽(③)보다 **어둡고 대비가 낮게** 그린다. 서는 면(`floor-top`)과 길이 한눈에 구분되어야 한다(참고 화면의 "캐릭터도 길도 잘 보이는" 기준).
- 지금 `bg-chapel.png`의 고딕 창·촛대 분위기를 조각으로 다시 나눠도 된다(경로 A).
