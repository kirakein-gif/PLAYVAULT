## 2. 참고와 금지

- 장르 수준의 감각(고딕 성채, 촛불과 달빛, 석재·철·천)만 참고한다.
- 특정 게임·작가·작품의 그림체를 흉내 내지 않는다. 이미지 생성 지시문에 특정 게임 이름이나 작가 이름을 쓰지 않는다.
- 기존 THE HOLLOW KEEP 타이틀 키아트(`games/the-hollow-keep/assets/title-*-hd-v2.webp`)는 **같은 인물의 외형 기준**으로만 쓴다. 고해상도 그림을 줄여서 스프라이트로 쓰지 않는다.
- 공용 자산(`assets/`)과 다른 게임(ABYSSFALL)의 그림은 수정하지 않는다. THE HOLLOW KEEP 픽셀 자산은 `games/the-hollow-keep/next/assets/pixel/`에만 둔다.

## 3. 그림체 기준

**빛과 색**
- 바탕은 차가운 청보라·회청색 어둠이다. 빛은 촛불(따뜻한 주황)과 달빛(창백한 청백) 두 가지만 쓴다.
- 빛은 기본적으로 왼쪽 위에서 들어온다. 횃불 근처만 예외로 한다.
- 재질마다 명암 단계는 3~5단계로 둔다. 그라데이션 디더링은 쓰지 않는다. 재질 표현용 디더링(돌결, 녹)만 허용한다.
- "베개 음영"(윤곽 따라 고르게 어두워지는 음영)을 피한다.

**윤곽**
- 1px 선택적 윤곽(sel-out)을 쓴다. 바깥 윤곽은 가장 어두운 색, 빛을 받는 쪽은 한 단계 밝은 색으로 그린다.
- 투명 배경과 맞닿는 가장자리에 중간 투명(안티에일리어싱)을 쓰지 않는다.

**실루엣과 가독성**
- 그림 1픽셀 = 실제 크기에서 실루엣만으로 Ethan과 Noah가 구분되어야 한다.
- 배경은 주인공·적보다 한 단계 어둡고 채도가 낮다. 플레이 판정이 있는 발판은 배경보다 밝고 윗면이 분명하다.

**주인공 외형 (타이틀 키아트 기준)**

| | Ethan · 빛 | Noah · 그림자 |
|---|---|---|
| 실루엣 | 곧고 넓은 어깨, 아래로 길게 퍼지는 롱코트 | 후드와 해진 망토 끝자락, 가늘고 긴 칼 |
| 머리 | 짧은 흑갈색 머리, 후드 없음 | 남색 후드, 그 아래 긴 흑청색 머리 |
| 옷 | 아이보리 롱코트 + 금색 장식, 어두운 가죽 조끼·벨트, 어두운 바지, 장갑·장화 | 남색 망토(보라 안감), 은 장식 검은 가죽 갑옷, 긴 장화 |
| 무기 | 오른팔의 금색 룬 장치, 파란 코어 발광 | 청록색으로 빛나는 가는 장검 |
| 강조색 | 금색 + 파란 발광 | 보라 + 청록 발광 |

## 4. 기술 규격 (자동 검사 대상)

### 4-1. 격자와 해상도
- 그림 해상도는 게임 좌표와 같은 **960×540**이다. 1단위 = 1픽셀이며, 시뮬레이션 수치는 바꾸지 않는다.
- **타일 크기는 30×30px**이다. 화면은 32×18칸이고, 960과 540을 모두 나누어떨어지게 하는 크기다. 2단계의 방은 이 격자로 만든다. 1단계 시험 방의 기존 지형은 격자와 맞지 않으므로, 타일을 잘라 그려도 된다.

### 4-2. 파일
- 모든 픽셀 자산은 **PNG(무손실), RGBA**로 저장한다. WebP·JPEG는 손실 압축으로 픽셀이 뭉개질 수 있어 쓰지 않는다.
- **원래 해상도로 저장한다.** 2배·3배로 키운 이미지를 저장하지 않는다. 확대는 화면에서만 한다.
- 투명도는 **0 또는 255만** 쓴다. 중간값은 쓰지 않는다.
- 모든 불투명 픽셀의 색은 `palette.json`에 있어야 한다. 팔레트는 **최대 64색**이다.

### 4-3. 스프라이트 시트
- 동작 하나를 가로 한 줄 띠로 만든다. 프레임은 왼쪽에서 오른쪽 순서이고, 한 시트의 프레임 크기는 모두 같다.
- 시트 크기는 `frameW × 프레임 수`, `frameH`이다.
- 모든 주인공 그림은 **오른쪽을 보는 방향**으로 그린다. 왼쪽은 렌더러가 좌우를 뒤집어 그린다.
- **기준점(pivot)**은 발 아래 가운데 픽셀이다. 시뮬레이션의 `(player.x + w/2, player.y + h)`가 이 픽셀에 대응한다.
- **발 위치:** 땅을 딛는 동작(`idle`, `run`, `land`)은 모든 프레임에서 불투명 영역의 맨 아래가 `pivot.y - 2` ~ `pivot.y` 사이에 있어야 한다. 발이 뜨거나 땅에 묻히면 안 된다.
- **몸 크기:** `idle` 첫 프레임의 불투명 높이는 시뮬레이션 `height`의 ±15% 안이어야 한다(Ethan 68, Noah 64). 판정 상자와 그림이 어긋나지 않게 하기 위해서다.

### 4-4. 필수 동작과 최소 프레임 수

| 동작 | 이름 | 최소 프레임 | 반복 | 비고 |
|---|---|---|---|---|
| 서 있기 | `idle` | 4 | 반복 | 숨쉬기, 망토·코트 흔들림 |
| 달리기 | `run` | 6 | 반복 | 발이 땅에 닿는 위치가 일정해야 함 |
| 제자리 점프 | `jump-standing` | 3 | 1회 | 상승·정점·하강. 몸을 세우고 무릎을 당긴 자세 |
| 달리며 뛴 점프 | `jump-running` | 3 | 1회 | 상승·정점·하강. **앞으로 기운 도약 자세**. `jump-standing`과 그림이 달라야 함(`jumpKind`, FOUNDATION_SPEC §4-1) |
| 착지 | `land` | 2 | 1회 | 짧게 웅크림 |
| 공격 | `attack` | 4 | 1회 | Ethan: 룬 장치 발사(준비 → 발사 → 반동 → 복귀). Noah: 베기(준비 → 휘두름 → 끝 → 복귀) |

효과(선택, 있으면 같은 규칙으로 검사): Ethan 룬탄 `fx-rune`(2프레임 이상), Noah 베기 궤적 `fx-slash`(3프레임 이상).

프레임별 시간은 틱 단위(1틱 = 1/60초)로 `manifest.json`에 적는다. 점프는 시간이 아니라 `vy`로 프레임을 고른다. 예를 들어 `vy`가 크게 음수면 상승, 0 근처면 정점, 양수면 하강이다.

### 4-5. 타일셋
- `tiles.png`는 가로·세로 모두 30의 배수 크기다.
- 필수 타일은 다음 세 가지다. `manifest.json`에 각 칸의 위치를 적는다.
  - `floor-top`: 바닥 윗면
  - `wall-fill`: 벽·바닥 속
  - `ledge`: 얇은 발판. 칸 위쪽부터 16px 높이, 시험 방 발판 두께
- 배경(선택): `bg-*.png`, 960×540, 같은 팔레트를 쓴다.

### 4-6. manifest.json 형식

```json
{
  "version": 1,
  "tileSize": 30,
  "palette": "palette.json",
  "heroes": {
    "ethan": {
      "body": { "w": 42, "h": 68 },
      "animations": {
        "idle": { "file": "ethan-idle.png", "frameW": 96, "frameH": 96, "frames": 4,
                  "pivot": { "x": 48, "y": 95 }, "ticks": [10, 10, 10, 10], "loop": true }
      }
    },
    "noah": { "body": { "w": 39, "h": 64 }, "animations": { } }
  },
  "tiles": { "file": "tiles.png", "cells": { "floor-top": [0, 0], "wall-fill": [1, 0], "ledge": [2, 0] } }
}
```

- `body.w`, `body.h`는 `sim.js` `CONFIG.heroes.*.width/height`와 같아야 한다.
- `ticks`는 프레임 수만큼의 양의 정수 배열이다. 점프는 생략할 수 있다.
- `palette.json` 형식은 `{ "colors": ["#0b0d17", "#1a1f33", ...] }`이다.

### 4-7. 화면 확대 (선명도)
- 캔버스 실제 해상도는 **960×k × 540×k**로 둔다. k는 정수이며, 화면에 표시되는 크기 × 기기 픽셀 비율(DPR) 이상이 되는 가장 작은 값이다.
- 게임은 `setTransform(k, 0, 0, k, 0, 0)`으로 그리고, `imageSmoothingEnabled = false`로 둔다. 이렇게 하면 픽셀이 정수 배로 커져 선명하다.
- 표시 크기가 실제 해상도보다 작으면 브라우저가 부드럽게 줄인다. 그래서 휴대전화처럼 비율이 정수로 떨어지지 않는 화면에서도 픽셀 폭이 들쭉날쭉하지 않다.
- 스프라이트·타일은 **정수 좌표**로 그린다. 시뮬레이션 좌표가 소수이므로 반올림해 그린다(판정은 바꾸지 않음).
- 창 크기·전체 화면이 바뀌면 k를 다시 계산한다.
- `window.HKPlaytest.artStatus()`는 `{ loaded: boolean, failed: string[] }`를 반환한다. 자산을 불러오지 못하면 현재의 도형 그림으로 대신 그리고, 게임은 계속 동작해야 한다.

## 5. 제작 과정 (이미지 생성 → 실제 픽셀아트)

이미지 생성 도구가 만든 "픽셀아트 느낌" 그림은 대개 픽셀 크기가 섞여 있고 가장자리가 흐려서, 그대로는 이 기준을 통과하지 못한다. 다음 순서를 따른다.

1. **콘셉트:** 이미지 생성으로 외형·자세 참고 그림을 만든다. 참고용이며 저장소에 넣지 않아도 된다.
2. **원래 해상도로 다시 그리기:** 목표 크기(예: 96×96 프레임)에 맞춰 격자를 다시 맞춘다. 단순 축소만으로 끝내지 않는다.
3. **팔레트 맞추기:** `palette.json` 색으로 양자화하고, 투명도를 0/255로 정리한다.
4. **손질:** 떠 있는 점, 두 겹 선(doubles), 끊긴 윤곽, 프레임 간 흔들림을 정리한다.
5. **기록:** `next/assets/pixel/PROVENANCE.md`에 사용한 도구, 전체 지시문, 손질 과정, 날짜를 적는다.
6. **검사:** `pixel-assets.cjs`와 `pixel-render.cjs`를 통과해야 한다.
