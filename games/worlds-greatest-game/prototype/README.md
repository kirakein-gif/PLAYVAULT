# 세계 최고의 게임 · 액션 프로토타입 v0.13 / APPROVED A

## v0.13 수평 테이블과 고정된 타격 구도

사용자 최종 지시인 '비스듬하게가 아닌 가로로'를 적용했습니다. 테이블의 긴 뒷모서리는 논리 y=540에 수평으로 놓이고, 양옆 짧은 모서리만 깊이 방향으로 벌어집니다. 사무실과 같은 그림체로 제작한 나무 상판·모서리 이미지를 사용해 기존 대각선 도형/줄무늬 나뭇결을 대체했습니다. 도구를 들어 올리면 테이블에 빈 그림자가 남지 않으며 냄비 그림자는 바닥면에 맞췄습니다. 손잡이와 인물 준비/RPS 배치는 유지했습니다.

양쪽 타격 때 적용하던 (108,110) 이동과 0.82배 축소를 제거했습니다. 상대 인물·테이블·배경은 타격 전후 같은 위치/크기를 유지합니다. 망치 머리만 짧은 장난감 비례로 다시 제작해 화면 안에 들어오도록 했으며 타격 그림 전체를 같은 정수리 접촉 앵커에 배치합니다. 에너지바는 머리 위 물체를 가리지 않게 옆 빈 공간으로 피합니다.

검증: Node 전투 27 + 진행 5 + Chrome 조작 22 + 고정 구도 1 = 55개. 고정 구도 검사는 양쪽 타격 전후 방어하는 인물의 머리와 테이블 일부를 실제 Chrome 화면에서 캡처해 픽셀이 동일함을 확인합니다. 준비·양쪽 타격·10개 포즈·가위바위보·냄비 착용을 육안 검수했습니다. 정지 포즈별 공격자의 자체 위치/그림 차이와 상대가 앞으로 숙이는 정도는 후속 미술 정합 대상이며, 이번 수정은 카메라 축소와 테이블 각도를 해결합니다.

새 아트의 전체 생성·편집 프롬프트와 파일은 `assets/approved-a/STAGE_PROVENANCE.md`에 기록했습니다. 이전 버전 파일은 제작 이력으로 보존합니다.

## v0.12 연속 카운트와 실제 화면 검수

매 판 3→2→1을 1초씩 표시합니다. 카운트 중 버튼/1·2·3으로 패를 미리 고르고 변경할 수 있으며 마지막 선택만 종료 순간 공개합니다. 이때부터 기존 1.7초의 직접 조작 시간이 시작됩니다. 선택하지 않았다면 패를 임의로 정하지 않고 입력을 기다립니다. 결과를 0.9초 보여준 뒤 다음 판 카운트로 자동 진행합니다. 에너지 0이면 자동 진행을 멈춥니다. 다시 시작과 포즈 미리보기 종료는 새 3초 카운트를 시작합니다.

이미지 로딩 후 첫 카운트를 시작하고, 미리보기에서는 경기 진행을 멈춥니다. 선택 패는 버튼 테두리로 표시합니다. 다음 판 수동 버튼은 제거했습니다. `round-flow.js`가 카운트·선택 예약·자동 다음 판을 관리하며 실제 전투 판정은 `engine.js`에 유지합니다.

검증: Node 전투 27개 + 흐름 5개 + 실제 Chrome 22개. 실제 시간의 3/2/1 화면, 종료 전 손 미공개, 최종 예약 패의 단 한 번 공개, 선택 미입력 대기, 네 판 자동 연결 및 에너지 0 종료를 확인했습니다. Chrome에서 실제 마우스 스윙·냄비 드래그·취소·리사이즈를 실행하고 각 단계 화면을 캡처해 직접 육안 검수했습니다.

육안 판단: 카운트와 선택 표시, 패 공개 및 에너지 변화는 읽을 수 있고 정상 동작합니다. 다만 준비↔RPS 사이 머리 위치가 조금 튀며, 정수리 타격의 넓은 구도와 다른 포즈 사이에 인물 크기/위치 차이가 뚜렷합니다. 상대 내려치기의 숙임도 과장되어 보입니다. 냄비 착용 시 에너지바가 냄비와 겹치는 문제는 착용 중 HUD를 빈 공간으로 옮겨 수정했습니다. 정지 그림을 바꾼 동작으로는 확인 가능하지만 자연스러운 일관된 연출로 판정하지 않았습니다. 이 문제는 이번 카운트 기능과 구분해 후속 아트 앵커/구도 정합 과제로 남깁니다.

## v0.11 정수리 타격과 에너지 경기

사용자 요청에 따라 양쪽 내려치기 정지 그림을 새로 제작했습니다. 망치의 아랫면이 머리 꼭대기를 향하며 얼굴 옆을 때리는 이전 프레임을 대체합니다. 타격 장면은 완성형 그림 전체를 축소한 넓은 구도이며 팔이나 도구만 별도 변형하지 않습니다. 입력이 활성인 단계의 카메라는 그대로입니다.

상대 명중 영역을 얼굴 중심의 큰 원에서 정수리 `(420,85,r26)`로 좁혔습니다. 상대 AI의 접촉 지점도 주인공 정수리 `(920,140,r32)`로 옮겼습니다. 빠른 스윙·이동량·접촉 검사는 유지하며 얼굴로 향한 스윙만으로 득점하지 않습니다.

각 인물 위 에너지바와 상단 숫자는 100에서 시작합니다. 명중은 상대 에너지 -25, 피격 또는 파울은 내 에너지 -25. 방어·상대 방어·무승부·빗나감은 감소하지 않습니다. 다음 판에도 에너지가 이어지고 한쪽이 0이면 승부를 끝냅니다. 경기 다시 시작은 양쪽 100으로 초기화합니다. 이전 3점 표시는 에너지 표시로 대체했습니다.

검증: Node 27개 + 실제 Chrome 20개. 정수리/얼굴 구분, 양쪽 에너지 감소·방어 유지, 네 번 명중 후 0에서 종료, 다음 판 유지/재시작 초기화, 기존 직접 마우스 조작과 정지 포즈 10개를 확인했습니다. 새 그림은 내장 image_gen으로 생성했으며 `assets/approved-a/CROWN_PROVENANCE.md`에 프롬프트를 기록했습니다. 프레임 사이 비례/위치 차이는 아직 후속 미술 QA 대상입니다.

## v0.10 도구 동작을 완성형 정지 포즈로 전환

사용자가 승인한 예시를 기준으로 양쪽 인물에 망치 잡기·들기·내려치기 3장, 냄비 잡기·착용 2장을 적용했습니다. 팔·손·몸·도구가 한 장에 연결된 그림이므로 소매 파츠를 늘리거나 관절을 보간하지 않습니다. 가위바위보는 승인한 기존 오른손 자세를 유지합니다.

테이블의 뿅망치와 냄비를 25% 키웠습니다. 망치 손잡이는 (480,610)으로 옮겨 커진 냄비와 겹치지 않게 했고, 냄비는 오른쪽 손잡이 입력 위치를 유지하며 커집니다. 들고 있는 도구는 각 완성형 그림에 포함됩니다.

마우스 누르기·드래그·스윙 속도/충돌·착용 유지 판정은 그대로 계산합니다. 화면은 입력 단계에 맞춰 정지 그림을 전환하므로 커서 위치를 매 프레임 그대로 따라 그리지는 않습니다. 클릭만으로 자동 공격/방어하지 않으며 승패도 미리 안내하지 않습니다. 상대 머리 판정 위치는 정지 포즈 기준으로 고정했습니다.

화면 아래 **정지 포즈 확인**에서 주인공/최주임과 다섯 포즈를 각각 고를 수 있습니다. 경기로 돌아가기로 미리보기를 끝냅니다. 이미지 로딩 실패 시 재시도 안내를 표시합니다.

검증: Node 24개 시나리오와 실제 Chrome 18개 검사. 양쪽 10개 포즈 및 RPS 9조합 캡처, 정지 미리보기의 픽셀 불변, 실제 마우스 공격/방어, 취소·파울·리사이즈·DPR2 확인. 새 이미지 출처와 전체 프롬프트는 `assets/approved-a/STILLS_PROVENANCE.md`에 기록했습니다.

## v0.9 오른팔로 도구 잡기·들기 연결

가위바위보의 오른손 자세를 기준으로 도구 구간의 어깨·몸통·잡는 손을 다시 맞췄습니다. 상대의 오른팔은 화면 왼쪽 어깨에서 나옵니다. 손목이 옆으로 이어지는 상대 손등/주인공 손바닥의 잡는 손을 사용하며, 손잡이를 중심으로 그려 손과 도구가 따로 움직이지 않게 했습니다. 냄비를 머리에 올릴 때는 손목과 잡는 손이 함께 회전합니다.

도구에 마우스를 가까이 대면 100ms 동안 팔을 내려 접근합니다. 이는 어느 도구에도 동일한 시각 동작이며 자동 획득이나 정답 안내가 아닙니다. 누르기·스윙·착용 입력에는 대기 시간을 추가하지 않았습니다. 상대는 RPS→테이블 접근→잡기→들어 올리기/타격→복귀의 연속 경로를 사용합니다. 팔꿈치의 전환은 팔 길이 제한 안에서 연결합니다.

상대가 전방으로 몸을 기울이면 그림과 머리 충돌 위치도 함께 움직이며, 피격 순간 위치를 보존한 뒤 복귀합니다. 상대 냄비도 머리에 맞게 커지고 손잡이 위치가 함께 이동합니다. 기존 즉시 RPS 입력과 직접 승패 판단은 유지합니다. 새 리깅은 2D 동작 블로킹이며 완성된 관절/손가락 애니메이션은 아닙니다.

검증: 규칙·기하·전환 22개 및 Chrome 17개. RPS 9조합, 양쪽 도구의 테이블/중간/머리 위 위치, AI 망치 접근·들기·타격과 냄비 착용을 고정 시점으로 캡처합니다. 새 아트와 전체 프롬프트는 `assets/approved-a/TOOLS_PROVENANCE.md`에 기록했습니다.

## v0.8 선택한 오른손 RPS 자세 반영

사용자가 고른 두 번째 전방 뻗기 샘플을 기준으로 상대와 주인공의 가위·바위·보 3종씩을 제작했습니다. 양쪽 모두 오른손이며, 상대의 손등과 주인공의 손바닥이 보입니다. 어깨부터 손목·손끝까지 이어진 상반신 포즈를 사용하므로 이전의 손 파츠를 옆으로 회전시킨 자세를 대체합니다. 주인공 팔꿈치의 깊이를 조절해 두 사람 손끝 사이에 간격을 둡니다.

RPS 구간에만 연결형 상반신 atlas를 사용하고, 도구 잡기 이후에는 기존 마우스/IK 조작으로 전환합니다. 머리 위치는 각 프레임의 앵커로 맞췄습니다. 선택 직후 패 공개와 입력 활성화는 그대로입니다. 기준 샘플은 `assets/approved-a/approved-rps-reference.png`, 전체 생성 프롬프트와 파일 설명은 `assets/approved-a/RPS_PROVENANCE.md`입니다. 9가지 패 조합과 준비/타격/착용을 캡처해 확인하며, 규칙·포즈 19개 및 Chrome 17개 검사를 사용합니다.

그림을 움직이는 레이어로 분리했습니다. RPS는 짧게 전완을 내미는 단축 포즈이고, 도구를 잡거나 공격할 때는 몸을 조금 앞으로 기울입니다. 소매의 화면상 길이는 원근을 반영한 투영입니다. 상대 팔꿈치가 반대 방향으로 순간적으로 뒤집히지 않도록 깊이 방향의 회전을 연결했습니다. 냄비는 테이블 위에서 바로 세워져 있고, 머리에 가까워지며 커지고 뒤집혀 착용됩니다. 가까워진 냄비의 손잡이 위치와 실제 방어 중심도 함께 계산합니다. 상대 피격에는 별도의 얼굴 표정과 머리 반동이 있습니다.

`render-a.js`가 일러스트 장면을 그리며 `art.js`가 PNG를 미리 읽습니다. 이미지 로딩에 실패하면 기존 도형 렌더러로 조작을 유지합니다. `file://` 직접 실행을 계속 지원합니다. 이미지 픽셀은 원본 그대로 저장하고 atlas 영역만 읽어 샘플링합니다.

검증: 규칙·포즈 19개, Chrome 17개 통과. 새 공격/방어, 원근 냄비의 손잡이/방어 중심, RPS와 AI 팔꿈치 연결, atlas 바운드, 실제 이미지 로딩, 이미지 실패 시 대체 화면을 확인했습니다. 1440/960px 입력 및 1280px DPR2 렌더를 검증하고 준비/RPS/명중/착용 캡처를 검수했습니다.

이는 A안 그림체의 **1차 동작 블로킹**입니다. 최종 3D 골격/손가락 리깅이나 완성 애니메이션이 아닙니다. 소매의 접합·손목 회전·몸의 기울기와 표정 전환은 후속 미술·동작 QA 대상입니다. 김과장 등 보스 확장과 기존 게임 변경은 없습니다.

## v0.6 테이블 방향만 회전

사용자 요청대로 대각선 인물 배치와 뒤통수 시점을 유지하고, 테이블의 긴 변이 화면 가로 방향으로 보이도록 90도 돌렸습니다. 상판·테두리·측면·다리를 같은 꼭짓점 설정에서 그립니다. 도구는 새 상판 안에 들어가므로 기존 잡기 위치를 유지했습니다. 규칙·포즈 17개와 Chrome 15개 검사 통과, 가로로 긴 상판과 기존 공격·착용 동작을 캡처로 확인했습니다.

## v0.5 대각선 테이블과 뒤통수 시점

상대는 왼쪽 위, 주인공은 오른쪽 아래에 배치했습니다. 머리 중심의 높이 차이는 120 → 190 논리 픽셀로 벌렸고, 테이블의 긴 변도 좌상단에서 우하단으로 내려가도록 원근 사각형을 회전했습니다. 테이블은 상대 앞에, 주인공의 등·어깨 뒤에 그려 어깨너머 깊이를 표현합니다.

주인공의 얼굴 면·눈·코·귀를 모두 제거하고 뒤통수, 목덜미, 등과 어깨만 그립니다. 머리 착용 영역과 어깨/타격 위치도 새 배치에 맞춰 이동했습니다. 도구는 회전한 테이블 위에 다시 놓았습니다. 한 인물당 하나의 활성 팔, 준비 중 손 비노출, 패 공개 즉시 입력은 유지했습니다.

검증: 규칙·포즈 17개 및 실제 Chrome 15개 검사 통과. 새 손잡이에서 직접 공격, 새 머리 위치에 냄비 착용, 작은 창의 좌표 변환을 다시 확인했습니다. 준비/RPS/명중/착용 캡처에서 대각선 테이블과 뒤통수 시점을 확인했습니다. 액션 시간 안에서 검사하는 브라우저 테스트와 화면 캡처를 분리해, 캡처에 걸린 시간이 공격 반응 시간을 소모하지 않게 했습니다.

## v0.4 한 팔 동작과 두 사람 사이 테이블

v0.3은 인물마다 RPS 팔과 도구 팔을 따로 그려, 두 팔이 몸을 가로질러 겹쳤습니다. 이번에는 **인물당 하나의 동작 팔**로 통합했습니다. 상대와 플레이어는 비스듬히 마주보고, 준비 중 손은 몸·테이블 뒤로 내립니다. 패 선택 때만 손을 내밀며, 도구를 잡으면 그 팔이 그대로 잡기/공격/착용으로 바뀝니다. RPS 팔이 별도로 남지 않습니다. 판정 후에는 팔을 내리고, 경기 종료에도 내민 손이 남지 않습니다.

화면 앞 장비 선반을 두 몸 사이의 원근 테이블로 바꾸고 망치·냄비를 나란히 배치했습니다. 최주임도 손 공개 → 테이블에 손 뻗기 → 도구 집기 → 공격/착용 순서로 움직입니다. 상대가 가져간 도구는 테이블에서 사라져, 공중에서 새 도구가 생기거나 같은 도구가 이중으로 보이지 않게 했습니다. 패는 손을 거둔 뒤에도 인물 위의 중립적인 패 이름으로 확인할 수 있고 승패 정답은 표시하지 않습니다.

v0.4 검증: 규칙·포즈 17개 시나리오 및 Chrome 15개 검사 통과. 추가 검사는 준비 중 손 비노출, 같은 어깨·뼈를 사용하는 RPS/도구 전환, 복귀 후 손 비노출, AI의 실제 테이블 손잡이 도달 이후 도구 획득을 확인합니다. 준비/RPS/명중/착용/크기 변경 캡처를 직접 확인했습니다. 조작 활성 시점과 경기 템포는 v0.3과 같습니다.

## v0.3 구도·팔·템포 수정

사용자 참고 이미지의 대결 배치를 바탕으로 상대는 왼쪽 3/4 정면, 플레이어는 오른쪽 앞 옆얼굴·어깨 구도로 가까이 배치했습니다. 참고 작품의 그림이나 캐릭터를 사용하지 않았습니다. 화면상 상대 얼굴은 폭 110 → 152, 플레이어 머리는 114 → 178로 확대했습니다. 큰 테이블은 아래쪽의 좁은 장비 선반으로 줄였습니다.

플레이어 상완/전완은 250/260 → 155/160, 상대는 165/175 논리 픽셀 고정 길이입니다. 상대의 공격·냄비·복귀와 두 사람의 RPS 팔까지 같은 2본 IK와 도달 범위 제한을 적용했습니다. 손이 어깨와 겹치는 경우에도 최소 관절 거리로 제한하므로 팔뼈가 늘어나거나 줄지 않습니다. 정지 자세에서는 손을 내리고, 경기 종료 후 공격 자세도 복귀합니다.

선택 즉시 양측 손을 공개하고 같은 업데이트에서 입력을 허용합니다(기존 650ms 공개 대기 제거). 상대 공격은 2.1 → 1.05초, 상대 냄비는 2.25 → 1.1초, 다음 판 대기는 1.25 → 0.3초입니다. 공격 제한은 1.7초, 무승부 대기는 0.45초, 냄비 정렬은 70ms로 줄였습니다. 승패는 여전히 사전 안내하지 않습니다.

## 실행

`prototype/index.html`을 Windows Chrome 또는 Edge에서 엽니다. 설치·빌드·서버·인터넷 연결이 필요 없습니다. 파일 실행은 실제 Chrome에서 검증했습니다. 기존 `../index.html`은 v0.1 원본입니다.

## 한 판의 흐름

1. 3→2→1 카운트 중 가위·바위·보 버튼 또는 1/2/3으로 패를 고릅니다. 종료 순간 두 손이 함께 공개됩니다. 결과 안내는 없습니다.
2. 손 공개와 동시에 자신의 판단으로 두 사람 사이 테이블 도구의 원형 손잡이 영역을 누릅니다. 이겼으면 망치, 졌으면 냄비, 비겼으면 기다립니다.
3. 망치는 **누른 채** 왼쪽 상대 정수리로 휘두릅니다. 최소 이동량 90, 속도 460 논리 픽셀/초와 충돌·방향을 검사합니다. 클릭만 하거나 천천히 대면 공격되지 않습니다. 상대는 약 1.1초 뒤 냄비로 막습니다.
4. 냄비는 오른쪽 테두리를 **누른 채** 오른쪽 앞 내 머리 위로 가져갑니다. 냄비 중앙이 내 머리 윗부분에서 38 논리 픽셀 안에 70ms 머물면 착용합니다. 상대 타격까지 계속 잡으세요. 놓거나 머리에서 벗어나면 방어가 풀립니다. 상대는 약 1.05초 뒤 공격합니다.
5. 판정 뒤 0.9초 후 다음 판 카운트가 자동으로 시작됩니다. 명중은 상대 에너지 -25, 피격·파울은 내 에너지 -25. 방어·상대 방어·빗나감·무승부는 에너지 감소 없이 재경기. 한쪽 에너지가 0이면 경기 종료입니다.

조기 도구 잡기, 잘못된 도구, 무승부 중 도구 사용은 사후 파울입니다. Esc, 창 초점 상실, 화면 이탈, 포인터 취소는 잡기를 해제합니다. 망치를 놓으면 헛스윙이며 냄비를 놓으면 방어가 풀립니다. 경기 재시작은 언제든 가능합니다. 효과음과 화면 흔들림은 별도로 끌 수 있습니다.

## 구조와 조정

- `config.js`: 경기 시간, 충돌/착용, IK 길이, 머리/손잡이 위치와 점수 기준.
- `engine.js`: DOM 없이 실행 가능한 상태·규칙·포인터 소유권·연속 충돌·IK 계산.
- `app.js`: Pointer Events, capture/해제, 논리 좌표 변환, 상태 UI, 오디오 이벤트.
- `art.js`, `render-a.js`: 완성형 정지 포즈와 기존 RPS atlas, 테이블 및 도구. 이전 `render.js`와 파츠 리깅은 제작 이력으로 남기고 실행 페이지에서 로드하지 않습니다.

`stillPose`는 입력 상태를 `idle/rps/hammer-pickup/hammer-lift/hammer-strike/pot-pickup/pot-wear` 중 하나로 매핑합니다. 관절 보간·호흡·흔들림 없이 완성형 포즈를 교체합니다. 내부 입력 도달 범위 계산은 유지합니다.
- `audio.js`: Web Audio 합성 효과음, 최대 12음, 음소거.

상태는 `select → react → resolve → select/end`. 손 공개와 `react` 진입이 동시입니다. UI는 내부 RPS 결과를 읽어 사전 승패나 정답 도구를 안내하지 않습니다. 상대의 준비 동작은 경기 행동으로 보입니다.

node games/worlds-greatest-game/prototype/tests/engine.cjs

## 현재 한계

사용자 요청에 따른 정지 포즈 기반 프로토타입입니다. 프레임 사이의 위치/크기는 완전 일치하지 않으며 커서의 정확한 위치를 연속적으로 표시하지 않습니다. 효과음은 코드 합성음입니다. 실제 스피커 청취, 낯선 사용자의 패 인지 속도, 장시간 플레이, 다른 브라우저 및 네이티브 Windows/Steam 배포는 별도 검증이 필요합니다. 터치 최적화·보스 확장·정식 오프닝은 이번 범위에 없습니다.
