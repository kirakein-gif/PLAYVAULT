# 입력·전투·파울 시스템 설계 v1.0

**핵심: PC 마우스 직접 조작이 최우선이며, 키 하나로 자동 공격/방어하는 UI는 개발 중 디버그 편의 기능 외에는 정식 조작이 아니다.**

## 1. 화면 및 대상

- 상대방은 3/4 정면, 가위바위보 손과 얼굴이 가까이 보인다.
- 내 캐릭터는 어깨너머 뒤통수/상체/팔이 일부 보인다. 냄비 착용 대상인 내 머리를 화면에서 찾을 수 있어야 한다.
- 망치/냄비는 테이블의 명확하고 서로 떨어진 손잡이 영역에 놓는다.
- 각 도구의 **손잡이 히트박스**, 플레이어 머리의 **방어 영역**, 상대 머리의 **타격 영역**을 구분한다.
- 마우스 1개를 공유하는 조작이므로 공격/방어는 상태별로 합법적인 도구가 다르지만, 잘못된 도구를 잡는 행위도 파울로 처리할 수 있게 설계한다.

## 2. 가위바위보

1. 경기 시작(동일한 신호)
2. 플레이어가 가위/바위/보 선택
3. 양측 손 공개 애니메이션
4. 손 모양이 충분히 분명해진 프레임부터 **플레이어가 직접 판단**
5. 내부 규칙 엔진만 win/lose/tie를 보유하고 UI는 미공개
6. 승리 시 망치, 패배 시 냄비를 잡아 처리. 무승부면 재경기
7. 판정 → 리액션 → 다음 판

- 손 모양은 관객/플레이어가 명료하게 볼 수 있도록 공개 타이밍을 통일한다.
- 버튼 위에 마우스를 올려 눈동자를 따라가는 보스의 경우, **선택 직전 시선 추적**과 손 공개 후 판정은 분리한다.
- 손 모양 공개 후에도 UI에서 승패를 미리 표시하지 않는다.

## 3. 망치 직접 공격

### 마우스 상호작용

- 손잡이 위에서 `pointerdown` → 망치 grab. 손이 망치를 쥐는 애니메이션.
- 누른 채 커서 이동 → 손목/팔꿈치/어깨 IK 또는 본 리깅으로 팔을 연결하고, 망치가 따라 움직임.
- **공격은 마우스가 상대 머리 타격 영역을 유효하게 통과하는 스윙**에서만 발생.
- 의도치 않은 소폭 마우스 움직임으로 자동 타격하지 않도록 최소 스윙 길이, 속도, 타격 방향을 검사한다.
- 타격 성공 시 딱 한 번 히트(다중 프레임 중복 판정 방지), hitstop과 반동/탄성/표정/효과음을 연결.
- 유효 스윙의 시작/끝을 기록하고, 사거리·속도 임계값을 설정 파일에서 조정 가능하게 분리한다.
- 타격이 빗나가거나 타임아웃되면 상대의 방어 또는 기회 소멸이 일관되게 처리된다.
- `pointerup`, 화면 이탈, `pointercancel` 시 grab은 안전하게 해제.

### 타격감

**anticipation → acceleration → collision → hitstop → recoil → recovery**.
속도만 올리는 것이 아니라 준비/반동 애니메이션과 사운드 타이밍을 조절한다. 카메라 흔들림은 과하지 않게, 축소/비활성 옵션도 고려.

## 4. 냄비 직접 방어

- 손잡이/테두리의 조작 영역에서 `pointerdown` → 냄비 grab 및 플레이어 팔 연동.
- 냄비를 자기 머리의 착용 위치로 가져간다.
- 위치/방향/시간이 유효하면 냄비가 머리에 씌워지는 애니메이션과 **defense-ready 상태** 진입.
- 상대 망치가 머리에 닿기 전에 defense-ready면 방어.
- 늦게 씌우거나 빗맞추거나 너무 일찍 놓치면 방어 실패.
- grab 도중 실제 머리 위치와 냄비의 겹침/깊이 우선순위를 정확히 그린다.
- 방어 성공시 '깡!' 금속 울림·냄비 진동과 피격과 다른 반동을 표현.

## 5. 명확한 상태 머신 (예시)

`INTRO → READY → HAND_SELECT → HAND_REVEAL → REACT → RESOLVE → RECOVER → READY`

- `HAND_REVEAL` 이전에는 공격/방어 무효 또는 규칙에 따른 파울.
- `REACT`에서는 입출력 기록, 스윙/냄비 충돌 검사, 상대 AI 행동을 동기화한다.
- `RESOLVE`에서 적법성, 시간, 실제 충돌 결과, 파울 여부를 결정한다.
- 파울 판정은 무조건 명중보다 우선하며, 승패 확인용 UI가 아닌 **사후 판정**만 표시한다.
- 입력이 연속적으로 발생해도 더블 히트/판정 중복/상태 꼬임 없이 동작한다.
- 마우스를 빠르게 왕복할 때도 움직임 이벤트 누락·불연속 점프를 경계한다.

## 6. 파울 규칙 (초기 제안 / 조정 가능)

| 상황 | 결과 |
|---|---|
| 플레이어 승리 → 망치 유효 타격 | 정상 공격, 상대 방어와 속도 비교 |
| 플레이어 승리 → 냄비를 집음 | 파울: 잘못된 도구 |
| 플레이어 패배 → 냄비 정상 착용 | 정상 방어 |
| 플레이어 패배 → 망치를 집음 | 파울: 잘못된 도구 |
| 무승부 → 망치/냄비를 잡거나 공격 | 파울 또는 경고, 경기 규칙에 따라 조정 |
| 도구가 머리에 닿지 않음 | 헛스윙/방어 실패 (파울과 별개) |
| 조작 시한 초과 | 공격 기회 상실 또는 방어 실패 |
| 상대의 눈치 보기·장비 조작 | 보스별 반칙 (심판의 일반 파울과 별개) |

- 첫 잘못 잡기는 경고, 반복은 감점 같은 구체적 점수 체계는 플레이 테스트로 조정.
- 파울의 **입력 조건, 판정, 애니메이션, 표시**를 분리한다.
- 관찰형 반칙은 게임 규칙 내 '보스 능력'으로 다루고, 파훼의 단서를 화면에 심는다.

## 7. 김과장 반칙: 입력 교란

- `HAND_SELECT` 중 커서 위치(가위/바위/보)를 김과장 눈동자가 부드럽게 추적.
- 진짜 장면 속 눈동자가 이동해야 하며 레이블/도움말에 미리 정답을 노출하지 않는다.
- 일정 시간 안에 **왕복 이동량/방향 전환/속도** 임계값을 넘기면 눈동자가 따라가지 못해 **dizzy** 상태 발생.
- 별 회전, 어지럼/실수 동작, 예측 정확도 저하로 이어진다.
- 클릭/선택 자체는 정상적으로 하고, dizziness는 플레이어의 자동 승리를 의미하지 않는다.
- 모바일의 손가락 드래그 상호작용은 추후 별도 설계한다.

## 8. 테스트 기준

- 손모양은 어른/아이 관계없이 구분하기 쉽다.
- 유효한 망치 타격과 헛스윙이 확실히 구별된다.
- 냄비를 자기 머리에 드래그하면 비현실적 순간이동 없이 착용된다.
- 플레이어가 도구를 잘못 집으면 정확히 파울로 처리된다.
- 프레임 저하/크기 변경/마우스 빠른 이동에도 판정이 과도하게 달라지지 않는다.
- 타격과 방어 각각 애니메이션/효과음이 체감상 시원하다.
- 개발 중 테스트 UI가 최종 화면의 정답을 누설하지 않는다.
