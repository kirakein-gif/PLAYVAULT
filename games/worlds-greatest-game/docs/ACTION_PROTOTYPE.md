# 1차 액션 프로토타입 · 기술 결정 및 검증 기록

## v0.11 정수리 타격과 에너지 경기

사용자 요청에 따라 양쪽 내려치기 정지 그림을 새로 제작했습니다. 망치의 아랫면이 머리 꼭대기를 향하며 얼굴 옆을 때리는 이전 프레임을 대체합니다. 타격 장면은 완성형 그림 전체를 축소한 넓은 구도이며 팔이나 도구만 별도 변형하지 않습니다. 입력이 활성인 단계의 카메라는 그대로입니다.

상대 명중 영역을 얼굴 중심의 큰 원에서 정수리 `(420,85,r26)`로 좁혔습니다. 상대 AI의 접촉 지점도 주인공 정수리 `(920,140,r32)`로 옮겼습니다. 빠른 스윙·이동량·접촉 검사는 유지하며 얼굴로 향한 스윙만으로 득점하지 않습니다.

각 인물 위 에너지바와 상단 숫자는 100에서 시작합니다. 명중은 상대 에너지 -25, 피격 또는 파울은 내 에너지 -25. 방어·상대 방어·무승부·빗나감은 감소하지 않습니다. 다음 판에도 에너지가 이어지고 한쪽이 0이면 승부를 끝냅니다. 경기 다시 시작은 양쪽 100으로 초기화합니다. 이전 3점 표시는 에너지 표시로 대체했습니다.

검증: Node 27개 + 실제 Chrome 20개. 정수리/얼굴 구분, 양쪽 에너지 감소·방어 유지, 네 번 명중 후 0에서 종료, 다음 판 유지/재시작 초기화, 기존 직접 마우스 조작과 정지 포즈 10개를 확인했습니다. 새 그림은 내장 image_gen으로 생성했으며 `assets/approved-a/CROWN_PROVENANCE.md`에 프롬프트를 기록했습니다. 프레임 사이 비례/위치 차이는 아직 후속 미술 QA 대상입니다.

## v0.10 도구 동작을 완성형 정지 포즈로 전환

사용자가 승인한 예시를 기준으로 양쪽 인물에 망치 잡기·들기·내려치기 3장, 냄비 잡기·착용 2장을 적용했습니다. 팔·손·몸·도구가 한 장에 연결된 그림이므로 소매 파츠를 늘리거나 관절을 보간하지 않습니다. 가위바위보는 승인한 기존 오른손 자세를 유지합니다.

테이블의 뿅망치와 냄비를 25% 키웠습니다. 망치 손잡이는 (480,610)으로 옮겨 커진 냄비와 겹치지 않게 했고, 냄비는 오른쪽 손잡이 입력 위치를 유지하며 커집니다. 들고 있는 도구는 각 완성형 그림에 포함됩니다.

마우스 누르기·드래그·스윙 속도/충돌·착용 유지 판정은 그대로 계산합니다. 화면은 입력 단계에 맞춰 정지 그림을 전환하므로 커서 위치를 매 프레임 그대로 따라 그리지는 않습니다. 클릭만으로 자동 공격/방어하지 않으며 승패도 미리 안내하지 않습니다. 상대 머리 판정 위치는 정지 포즈 기준으로 고정했습니다.

화면 아래 **정지 포즈 확인**에서 주인공/최주임과 다섯 포즈를 각각 고를 수 있습니다. 경기로 돌아가기로 미리보기를 끝냅니다. 이미지 로딩 실패 시 재시도 안내를 표시합니다.

검증: Node 24개 시나리오와 실제 Chrome 18개 검사. 양쪽 10개 포즈 및 RPS 9조합 캡처, 정지 미리보기의 픽셀 불변, 실제 마우스 공격/방어, 취소·파울·리사이즈·DPR2 확인. 새 이미지 출처와 전체 프롬프트는 `assets/approved-a/STILLS_PROVENANCE.md`에 기록했습니다.

## 기준선 분석

main의 v0.1은 `index.html` 한 파일(HTML/CSS, IIFE JavaScript, Canvas 2D, Web Audio)이며 외부 패키지가 없다. `chooseHand → enterReaction → doReact → finalize`가 타이머와 DOM에 결합되어 있다. `requestAnimationFrame`은 화면과 반응 제한 시간을 함께 갱신한다. 입력은 RPS 1/2/3, 공격 A, 방어 D 및 클릭이다. 손 공개 DOM과 활성 도구 표시가 결과를 먼저 노출한다. 캐릭터 팔은 고정 도형이며 도구와 연결되어 있지 않다. 오프닝과 김과장 테스트는 기존 파일에 보존한다.

## 기술 선택

| 기준 | HTML5 Canvas 개선 | Godot 2D 전환 |
|---|---|---|
| PC 마우스 | Pointer Events, capture, 좌표 변환 직접 제어 | InputEvent 및 전용 장면 구축 필요 |
| 팔·애니메이션 | 2본 IK와 절차적 모션으로 조작감 검증 가능 | Skeleton2D/AnimationPlayer로 후속 제작에 유리 |
| Steam Windows | 별도 데스크톱 패키징 및 Steam 연동 필요 | 네이티브 export 파이프라인에 유리 |
| 유지보수 | 규칙/렌더/입력 분리, 외부 의존성 없음 | 장면·리소스 제작 구조 도입 필요 |
| 사용자 확인 | 파일을 브라우저에서 바로 실행 | 에디터 또는 내보낸 빌드 필요 |

**이번 선택: HTML5.** 손맛의 반복 검증을 우선한다. Godot 이전은 아트 파츠와 조작 임계값이 안정된 후 별도 결정한다. 엔진 비교는 현재 프로젝트 요구에 대한 설계 판단이며 배포 기능을 이번 작업에서 검증한 것은 아니다.

## 범위와 단계

모든 변경은 이 게임 폴더 안에만 둔다. `prototype/`를 신규 경로로 만들고 원본 v0.1은 수정하지 않는다. 상대는 최주임 한 명, 세 점 경기 및 재도전. 정식 아트·오프닝·보스 확장은 제외한다.

1. 문서와 기술 선택: 원본·계획 문서 확인, 변경 범위 검사.
2. 화면/상태: 3/4 상대와 어깨너머 플레이어, 같은 시각 양측 손 공개, 결과 미노출. 규칙 엔진을 DOM에서 분리.
3. 직접 조작: 손잡이 grab, 포인터 소유권, 팔 2본 IK, 망치 머리의 연속 선분 충돌/길이/속도/방향, 냄비 머리 정렬 및 착용 유지.
4. 판정: 틀린 도구·조기 도구·무승부 도구 파울, 한 번만 판정, 상대 방어/공격 지연, 빗나감·방어 실패, 세 점 종료.
5. 타격감/검증: hitstop, 반동, 표정, 궤적, 서로 다른 합성 효과음, 흔들림/음소거 설정. 규칙 회귀 및 실제 브라우저 입력 검증.

각 단계 검증 후 커밋한다. 피드백이 도착하면 후속 조정에 반영한다. 입력 수치는 `prototype/config.js`에서 조정한다. 테스트 전용 결정적 상대 패는 일반 UI와 분리한다.

## 완료 판정과 한계

실제 pointerdown/move/up 경로로 명중·느린 이동 거부·헛스윙·냄비 착용/이탈·파울·취소·크기 변경을 확인한다. 자동화가 다루는 사실과 인간의 주관적 손맛 평가는 구분한다. 도형 기반 임시 아트와 합성 효과음이며 최종 극화체 아트나 Steam 배포판이 아니다.

- 내장 이미지 생성으로 일러스트 머리/몸통 4종, 소매 4종, RPS/잡기 손 4종, 피격 표정, 사무실 배경 제작. A 기준 이미지·제작 경로·전체 프롬프트는 `prototype/assets/approved-a/PROVENANCE.md`에 보존.
- `art.js`의 이미지 로딩과 `art-bounds.js` atlas 샘플링, `render-a.js`의 장면 합성 추가. 머리/몸통/팔을 독립적으로 그려 손목과 도구 연결, 상체 기울기, 피격 표정·반동을 적용. 파일 직접 실행과 로딩 실패 시 조작 유지.
- 몸 가까이 내미는 RPS는 짧은 투영 포즈, 도구에는 어깨 이동/기울기와 깊이 단축을 사용. AI 팔꿈치는 양쪽 IK 해 사이를 깊이 방향으로 연결. 2.5D 블로킹이며 최종 골격/손가락 리깅은 아님.
- 냄비를 머리로 가져올 때 원근 확대·뒤집기 및 손잡이 오프셋을 방어 중심 계산과 일치시킴. 망치는 테이블에 가로로 놓임.
- 규칙·포즈 19개와 Chrome 17개 통과. atlas 바운드, 새 직접 공격/착용, 냄비 중심, 팔꿈치 연속성, 이미지 실패 대체, 크기/DPR 확인. 캡처에서 A 구도와 피격/방어를 검수. 기존 게임과 v0.1 수정 없음.

### v0.4 사용자 피드백 반영

### v0.3 사용자 피드백 반영

- 요청: 참고 이미지처럼 인물을 크게 근접 배치, 고무처럼 보이는 팔 수정, 패 공개 후 즉시 조작.
- 기술 원인: 플레이어 뼈 길이 250/260이 화면 인체 비례보다 과도했고 상대 팔은 길이 제한 없이 선분으로 손을 연결했다. 손이 보인 뒤에도 공개 상태 종료까지 grab이 파울이 되는 불일치가 있었다.
- 변경: 상대 왼쪽/플레이어 오른쪽 앞의 상반신 구도. 얼굴/머리 확대와 하단 선반. 플레이어 155/160, 상대 165/175의 고정 길이 IK 및 모든 free-hand/AI 경로에 도달 범위 제한. 상대 공격 이후 복귀와 경기 종료 자세 정리.
- 입력: 손 선택과 동시에 전체 손모양 공개 및 react 진입. 650ms 대기 제거. 상대 공격 1050ms, 냄비 방어 1100ms, 회복 300ms로 조정. 결과 사전 노출 없음.
- 검증: 규칙·기하 15개, Chrome 15개 통과. 어깨-팔꿈치-손목 길이를 AI 공격/방어/복귀 전 구간 및 극단적 마우스 목표에서 확인. Chrome 1440/960px 입력 및 1280px DPR2 렌더 확인. 새 준비/명중/착용/리사이즈 캡처 검수. 아트는 여전히 절차적 임시 그래픽.

- 최초 브라우저 검증 도구가 생성자에 저장된 난수 함수를 교체하지 못해 패 고정에 실패했다. 페이지 로드 전 난수 래퍼를 주입하도록 테스트를 고쳤으며 일반 게임에 테스트 전용 상태를 추가하지 않았다.
- pointer capture 상태에서 `pointerleave`만으로 이탈을 처리하면 누른 상태가 남을 수 있어, 포인터 좌표 경계 검사와 명시적 capture 해제를 추가했다.
- 버튼에 초점이 남아 있어도 1/2/3 선택이 가능하게 키보드 입력 예외를 줄였다. 텍스트/설정 입력은 계속 보호한다.
