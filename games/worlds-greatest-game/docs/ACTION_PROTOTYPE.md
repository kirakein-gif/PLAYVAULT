# 1차 액션 프로토타입 · 기술 결정 및 검증 기록

## 기준선 분석

main의 v0.1은 `index.html` 한 파일(HTML/CSS, IIFE JavaScript, Canvas 2D, Web Audio)이며 외부 패키지가 없다. `chooseHand → enterReaction → doReact → finalize`가 타이머와 DOM에 결합되어 있다. `requestAnimationFrame`은 화면과 반응 제한 시간을 함께 갱신한다. 입력은 RPS 1/2/3, 공격 A, 방어 D 및 클릭이다. 손 공개 DOM과 활성 도구 표시가 결과를 먼저 노출한다. 캐릭터 팔은 고정 도형이며 도구와 연결되어 있지 않다. 오프닝과 김과장 테스트는 기존 파일에 보존한다.

## 기술 선택

| 기준 | HTML5 Canvas 개선 | Godot 2D 전환 |
|---|---|---|
| PC 마우스 | Pointer Events, capture, 좌표 변환 직접 제어 | InputEvent 및 전용 장면 구축 필요 |
| 팔·애니메이션 | 2본 IK와 절차적 모션으로 조작감 검증 가능 | Skeleton2D/AnimationPlayer로 후속 제작에 유리 |
| Steam Windows | 별도 데스크톱 패키징 및 Steam 연동 필요 | 네이티브 export 파이프라인에 유리 |
| 유지보수 | 규칙/렌더/입력 분리, 외부 의존성 없음 | 장면·리소스 제작 구조 도입 필요 |
| 사용자 확인 | 파일을 브라우저에서 바로 실행 | 에디터 또는 내보낸 빌드 필요 |

**이번 선택: HTML5.** 손맛의 반복 검증을 우선한다. Godot 이전은 아트 파츠와 조작 임계값이 안정된 후 별도 결정한다. 엔진 비교는 현재 프로젝트 요구에 대한 설계 판단이며 배포 기능을 이번 작업에서 검증한 것은 아니다.

## 범위와 단계

모든 변경은 이 게임 폴더 안에만 둔다. `prototype/`를 신규 경로로 만들고 원본 v0.1은 수정하지 않는다. 상대는 최주임 한 명, 세 점 경기 및 재도전. 정식 아트·오프닝·보스 확장은 제외한다.

1. 문서와 기술 선택: 원본·계획 문서 확인, 변경 범위 검사.
2. 화면/상태: 3/4 상대와 어깨너머 플레이어, 같은 시각 양측 손 공개, 결과 미노출. 규칙 엔진을 DOM에서 분리.
3. 직접 조작: 손잡이 grab, 포인터 소유권, 팔 2본 IK, 망치 머리의 연속 선분 충돌/길이/속도/방향, 냄비 머리 정렬 및 착용 유지.
4. 판정: 틀린 도구·조기 도구·무승부 도구 파울, 한 번만 판정, 상대 방어/공격 지연, 빗나감·방어 실패, 세 점 종료.
5. 타격감/검증: hitstop, 반동, 표정, 궤적, 서로 다른 합성 효과음, 흔들림/음소거 설정. 규칙 회귀 및 실제 브라우저 입력 검증.

각 단계 검증 후 커밋한다. 피드백이 도착하면 후속 조정에 반영한다. 입력 수치는 `prototype/config.js`에서 조정한다. 테스트 전용 결정적 상대 패는 일반 UI와 분리한다.

## 완료 판정과 한계

실제 pointerdown/move/up 경로로 명중·느린 이동 거부·헛스윙·냄비 착용/이탈·파울·취소·크기 변경을 확인한다. 자동화가 다루는 사실과 인간의 주관적 손맛 평가는 구분한다. 도형 기반 임시 아트와 합성 효과음이며 최종 극화체 아트나 Steam 배포판이 아니다.
