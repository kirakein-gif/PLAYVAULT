## 이력 복원 결과와 남은 문제

- [WORK_LOG의 복원 연대기·전체 색인](WORK_LOG.md#전체-커밋-색인), [CHANGELOG](../CHANGELOG.md)에 최초 등록부터 현 tip까지의 주요 추가·구조 변경·수정·버전 표기를 연결했다. 앞선 관리 작업 로그와 기존 README·게임 문서·CODEX_HANDOFF는 보존했다.
- **ECLIPSE:** 4층 결과→12층 분기 캠페인→24층/8구역으로 확장. 공용 atlas→별도 art·음원·회귀 검사, 봉인/계단, 환경 위험, 역할별 전투/유물, 소환 준비와 돌진 충돌까지 추적했다. 보스 출구 정지·보상 경합·패널 겹침·공격 취소·atlas 오염은 과거 수정 커밋이 확인되며, 이 목록을 현재 재현된 버그로 취급하지 않는다. 최신 소스의 잔여 오류·실기기 장기 안정성은 확인 불가. 다음 작업은 실제 사용자 요청과 담당 확인 후 정한다.
- **HOLLOW KEEP:** 첫 프로토타입→몸체 초기화 수정→이동/연타/공격 자세/회복 박자→sprite/backdrop→가로 화면 강제→첫 구역 축소 및 보스 귀환→HD 키 아트 흐름을 확인했다. 보스 사후 귀환 연결은 `60a9f8d`에 수정되었다. 30개 방 정의가 모두 현재 챕터에서 사용되는지, 실제 전 경로 완료·모바일 브라우저별 동작·v8 이후 공식 제품 번호는 확인 불가. 기존 README의 일반적 30방 설명을 현재 검증 결과로 확대하지 않는다.
- **세계 최고의 게임:** main 단일 HTML 원본/기획과 별도 prototype v0.2–v0.13을 구분했다. 초기 3점 경기는 최신 100 에너지 체계로, 초기 팔 IK 중심 표현은 최신 정지 포즈 렌더링으로 교체되었다. 내부 판정의 IK/도달 계산이 남아 있는 것과 연속 시각 모션 완성은 다르다. 브랜치 문서의 포즈 정합·자연스러운 연결·청취·터치/장기 QA·Windows/Steam 검증 한계는 남아 있으며 이번에 해결하지 않았다.
- **기록 간 차이:** ECLIPSE README의 12층/과거 버전, HOLLOW KEEP의 역사적 방 구성, prototype 문서의 초기 3점/후기 에너지 설명은 시점이 다르다. 이력은 보존하고 최신 동작 판단은 해당 tip의 실행 소스와 테스트를 우선한다.
- **테스트 상태:** 이번 보강은 문서/근거/전체 커밋 색인 검증만 수행한다. 앞선 문서 작업의 Node 3종 통과 및 온보딩 브라우저 통과를 새 실행으로 재기록하지 않는다. 과거 버전 전체 QA와 prototype의 55개 문서 보고를 독립 재검증한 것은 아니다.
- **외부 차단:** 사용자 `api.github.com` 언급 후에도 `gh api .../pulls`가 Forbidden. PR/승인·배포 상태 확인 불가. 현재 문서 브랜치에 최종 결과를 저장하고 API 접근이 가능해지면 기존 PR 여부를 확인한 뒤 제출한다. 사용자 승인 없이 병합·배포하지 않는다.

다음 AI는 5개 관리 문서를 매 작업 검토·갱신하고, 담당/PC 작업 확인 → 사용자 요청 범위 결정 → 해당 브랜치 소스·검증 재현 순으로 이어간다. 단순 기록 복원을 게임 작업의 승인으로 보지 않는다.
